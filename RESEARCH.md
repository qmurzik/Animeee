# Исследование и ограничения

- [YummyTV](https://github.com/Helandy/YummyTV): Android-проект с отдельными модулями источников и плеера. AniLibria отдаёт HLS с несколькими разрешениями и разметку сегментов. Для ряда сторонних источников используется собственный сервер проекта `POST /availability`; подключение требует проверенных соответствий и условий работы этого сервера. AniDub и AnimeVost дополнительно разбирают страницы и данные плеера. Наличие модулей не подтверждает работоспособность или право встраивания. Лицензия репозитория — CC BY-NC 4.0; код не копировался.
- [Yummy Lampa](https://github.com/yummyanime/yummy-lampa-plugin) описывает каталог, расписание и проигрывание доступных источников; публичный API списка тайтлов и видео подключён для поиска озвучек по точному MAL ID для поиска записей переводов; в текущей версии веб-плеер удалён. Aksor API возвращает варианты качества, но проверенные записи содержат только DASH, который AVPlayer напрямую не поддерживает. Отдельного файла LICENSE при просмотре корня не обнаружено; права на копирование не предполагались.
- [AnixApp](https://github.com/Maks1mio/anixapp) — клиент Anixart API; лицензия PolyForm Noncommercial 1.0.0. Код не копировался.
- [AniLiberty API](https://api.anilibria.app/api/docs/v1/) и [AniSkip](https://api.aniskip.com/api-docs) изучены по доступным ответам API. `anilibria.top/api/v1` вернул каталог, поиск, карточку и HLS-плейлист. Доступность и права на воспроизведение могут зависеть от сети, региона и условий источника.
- Для AniSkip используется MAL ID, предоставленный непосредственно AniLibria, и данные принимаются только при разнице длительностей не более 3 секунд. Данные источника имеют приоритет. Даже совпадающая длительность не гарантирует идентичный монтаж; автопропуск выключен по умолчанию.

Проверки `python3 -m unittest discover -s tests -v` проверяют актуальные ответы сервисов; это не тесты Swift. Реальное декодирование видео, iOS, PiP, AirPlay, память и офлайн-сценарии требуют проверки на устройстве. Текущий клиент является незавершённым, не реализует большинство запрошенных функций и собран Xcode для iphoneos, но пока не проверен на устройстве.

Сервер YummyTV `/availability` при проверке без подписи вернул 401; подпись или ограничения сервера не обходятся. При проверке YummyAnime для MAL ID 1735 API вернул озвучки и веб-плееры; один HTML iframe ответил HTTP 200. Это не проверка просмотра видео.

## Нативные адаптеры следующей версии

Для поддержки MPEG-DASH добавлен VLCKitSPM 3.6.0, сохранён AVPlayer для AniLibria. Адаптер Aksor использует `/api/video/{id}` и возвращённые качества. DASH с ContentProtection не принимается. CVH использует публичные интерфейсы, которые вызывает оригинальный плеер YummyAnime: playlist и video. При сериализации выбирается точное соответствие voiceStudio и номера серии. Адреса CDN не переписываются; закрытые, недоступные и регионально ограниченные ответы приводят к ошибке источника.

Измерения: MPD Aksor для тестовой серии — HTTP 200, метки ContentProtection отсутствуют; FFmpeg декодировал четыре секунды с кодом 0. CVH MP4 FumoDub — HTTP 206 для диапазона, FFmpeg также декодировал четыре секунды с кодом 0. Для другого CVH-варианта запрос CDN отклонён сетевым окружением: доступность всех переводов не заявляется. Для одного текущего тайтла API YummyAnime вернул 25 вариантов CVH, включая студии и субтитры; это проверка каталога переводов, не каждого видеопотока.

Нативные сборки VLCKit для ARM64 проходили GitHub Actions. Проверка симулятора добавлена отдельно; начальная ошибка архитектуры x86_64 исправлена указанием ARM64. Актуальный статус смотрите в последнем Actions run. Физического устройства для испытания нет.
