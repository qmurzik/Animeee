# Источники 0.8

Проверено 2026-11-03. Приложение различает каталог, команду перевода и видеобалансер.

## AnimeLIB (Anilib, не AniLibria)

Новый независимый поиск: «Поиск → Другие источники → AnimeLIB».
Нативный список сезонов/серий и реальных переводов каждой выбранной серии; запоминаются последняя открытая серия и приоритет команды перевода.

Адрес сайта: https://animelib.org (старый https://anilib.me). Публичный текущий клиент сайта использует API https://hapi.hentaicdn.org с Site-Id: 5, Content-Type, Client-Time-Zone и контекстом Origin/Referer сайта; имя общего CDN не означает использование каталога других сайтов. Поиск ограничен site_id[]=5.

Подтверждены HTTP 200 обычным публичным запросом через Firecrawl basic:

- `/api/anime?q=naruto&site_id[]=5`: Naruto, slug `11--naruto-anime`, явная ссылка Shikimori ID 20.
- `/api/episodes?anime_id=11--naruto-anime`: 220 серий.
- `/api/episodes/455`: AniDUB, RISE I voices, 2×2, OPRUS, Субтитры; все пять плееров Kodik.

Для карточек AnimeLIB с явным Shikimori ID также выполняется независимый поиск точного соответствия в YummyAnime. При совпадении предлагается отдельная кнопка нативного просмотра с указанием реального поставщика видео. Ошибка этого поиска не блокирует серии AnimeLIB.

Эти ответы содержат iframe URL, **не прямые MP4/HLS**. Поэтому просмотр для них реализован отдельным WKWebView с официальной страницей плеера, видимым предупреждением о возможностях и кнопкой Safari. Это не интеграция Kodik в VLC. Качество и полный экран регулирует сам источник. Прогресс до секунды, автоматическая следующая серия и пропуск приложения в этом режиме недоступны. Нативные Aksor/CVH/AniLibria продолжают работать своим прежним способом.

Сайт для входа открывается в стандартном WebKit-хранилище приложения. Приложение не извлекает токены/куки AnimeLIB. Функциональность собственного плеера AnimeLIB после входа и на физическом iPhone не подтверждена. При запросах без Origin/Referer API возвращал HTTP 403 из Linux и macOS. Обычный публичный запрос с конфигурацией клиента сайта получил HTTP 200 из Linux; браузерное получение также успешно. В адаптер и живой CI-probe добавлены те же заголовки. Это не требует токенов или обхода CAPTCHA; результат именно macOS-сборки записан в sources-report.json. Проверка через один маршрут всё равно не гарантирует доступ на iPhone.

## Shikimori

Реальный поиск `/api/animes?search=...&limit=30`, постеры и стабильный ID. При открытии карточки приложение ищет её в YummyAnime и допускает переход к нативному просмотру **только при единственном совпадении remote_ids.shikimori_id**. Название служит поисковым запросом, но не доказательством совпадения. Источник серий подписан YummyAnime; может требоваться его авторизация.

`/api/animes/:id/videos` по-прежнему отдельно показывает клипы, трейлеры, опенинги и эндинги. Непосредственного публичного API полных серий Shikimori не подтверждено. Не заявляем, что Shikimori отдаёт эти полные серии.

## AnimeGO — экспериментальный, недоступен при проверке

Реализован адаптер публичных `/search/anime?q=...`, `/player/:animeID`, `/player/videos/:episodeID`: каталог, номера серий, названия переводов и iframe URL. Парсер проверен на контрактных фикстурах, но свежий успешный ответ и воспроизведение не подтверждены.

https://animego.org перенаправляет на https://animego.me. Оба дают HTTP 500 (проверены обычным запросом и Firecrawl basic). Интерфейс показывает конкретный HTTP-код. Не добавлены неподтверждённые клоны с похожими названиями.

## Зеркала

«Настройки → Источники и зеркала»: отдельные HTTPS-адреса сайта и API, сохранение, проверка живого поиска. Пустые поля восстанавливают стандартные адреса.

При сетевой ошибке или 5xx API пробует следующий адрес: пользовательский, затем подтверждённые стандартные. AnimeGO имеет два стандартных адреса, но редирект на один и тот же не создаёт независимого рабочего зеркала. Авторизация 401/403 и лимиты 429 останавливают повтор; защиты не обходятся.

Адрес сайта применяется к ссылкам на карточки/авторизацию. Внутренние CDN, iframe и подписанные адреса видео не переписываются. Переключение зеркал API не равно миграции аккаунта или позиции встроенного веб-плеера. API-запросы новых адаптеров выполняются без токенов YummyAnime и без WebKit cookies. Пользовательский адрес должен принадлежать доверенному сервису.

## Проверка

Swift unit-тесты: HTTPS/дедупликация зеркал; 503→следующий адрес; остановка на 403; отсутствие передачи токенов; Site-Id; точные внешние ID; порядок серий; отдельные студия/перевод/балансер; отклонение javascript URL; атрибуты AnimeGO; Shikimori не выдаёт клипы за серии.

XCUITest: переход в настройку источников и отклонение некорректного зеркала. Существующие реальные тесты полноэкранных кнопок и Aksor/CVH сохранены. Успешная сборка IPA сама по себе не подтверждает работу новых веб-плееров на физическом iPhone.
